- **Epic:** [lake#260](https://github.com/oramasearch/lake/issues/260)

## Verdict

The core loop **works and is fast**: a 200-row CSV uploaded in 0.3 s, a pipeline was built from one
sentence in under 10 s, and training ran in 2.6 s to an honest report (drivers, the 20 most at-risk
accounts, and a *What This Run Cannot Tell You* section). But a newcomer cannot find that loop without
help, the model it produces **cannot be called from outside lake**, the **Project Agent claims pipeline
changes it never made**, and there is **no documentation** anywhere in the product.

## Per job

**J1 Orient.** Home: *"Design, train, and ship AI on your own data"*, three cards, buttons *Open your
repositories* and *See your deployments*. The Train card says *"Put datasets and models in
repositories"*, but Train → Data works on workspace datasets: two data stories. No *Get started*, no
Docs or Help; `/docs` answers `{"error":"artifact does not exist","ok":false}`. The Ship card says
installing Liquid *"requires access to its source repository"*.

**J3 Load data.** Train → Data: Connections, Datasets (a long list), then collapsed *Upload a file* and
*Generate a dataset*, then Storage (14 options, 13 *not yet*, some citing *lake#196 phase 2*). Upload
of `ux-review-churn.csv` (200 rows): no confirmation, page back at the top, dataset listed as JSONL.
API: `workspace_act upload_dataset` answered `required property 'table_name' not found` (no `path`),
then 200 rows in 0.33 s; a GET to `workspace_query` answers *no such route* (it is POST-only). MCP: same
call, done.

**J4 Look.** Dataset page: columns alphabetical, no types, no rows, no stats; partitions with blob refs
and owner-node UUIDs; no *Train on this* action.

**J5/J6 Design and train.** New Project (name, description, decision) → project page → *Build a
Pipeline* from *"Predict the churned column of the ux_review_churn dataset from …"*: in under 10 s a
7-step **churn skeleton** (a template that invented a `warehouse.events` source and ignored the named
dataset and columns). The graph view is clear. Approve → *Train on* `datasets.ux_review_churn` → *Check
and run* → run page (title a UUID; project and pipeline as UUIDs) → succeeded in 2.6 s. Report: churn
rate 0.285, weights (support_tickets 46.7, tenure 21.8, spend 21.6, failed_payments 19.5), top 20 at
risk, and *held_out_auc: this run set no holdout_fraction* because the hold-out field's `0.2` is a
placeholder. `plan` (categorical) was dropped silently. Lineage says `warehouse:customers →
warehouse:events`; the missing `load_activity` step reports *succeeded*. The workspace's `run`
description admits *"other graphs run structurally"*: only churn-shaped pipelines truly train.

**J8 Ship.** Ship → Models: six `churn_model` rows, no score or date, empty RUN, *Publish* and
*Unpublish* on each. `expose_model {model: <id>}` → `/v1/models/<id>/predict`; from outside lake every
path answers *no such route*.

**J9 Agents.** Ask Orama opens as its own page with `from=/design/pipeline` (project and graph lost).
Asked to remove a step and set a 20 % hold-out on *churn skeleton*, it delegated to the Project Agent,
which answered *"updated … in place"*. Nothing changed (browser, API `get_pipeline`, MCP). Steve's
requirement: the Project Agent should modify a project's pipeline, which today it cannot.

**J10 Developer.** Developer → MCP: copy-ready setup for Claude Code, Cursor, Claude Desktop and curl,
the skill, llms.txt, and worked flows (pipeline, Postgres, volume, search). It lacks *load data* and
*train*; it says keys *never outlive your sign-in*, stale since opt-in never-expiring keys (lake#234).

**Phone width (390 px).** Navigation becomes a horizontal strip; the graph and the Runs table scroll
sideways, dominated by UUID columns. No console errors.
